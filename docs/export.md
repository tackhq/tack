# Export

`tack export` compiles a playbook into a standalone `bash` script per host,
resolving variables, templates, conditionals, loops, and tags **at export
time**. The result is a human-readable artifact that reproduces what tack would
send through the local connector.

## Why export?

- **Compliance audits** — reviewers read the exact shell commands that will run
  on production, not YAML abstractions.
- **Air-gapped / restricted hosts** — a host that cannot run tack can still
  receive and execute a plain shell script.
- **Debugging** — "why did this task do X?" is easiest to answer by reading the
  literal command.

The emitted script is a **snapshot**. Re-export whenever the playbook, inventory,
or target facts change.

## Quick start

```bash
# Print a script for a single host to stdout
tack export setup.yaml --host web01

# Write it to a file
tack export setup.yaml --host web01 --out-file web01.sh

# One script per inventory host, into a directory
tack export setup.yaml --all-hosts --out-file ./scripts/

# Validate without writing anything; non-zero exit if anything is unsupported
tack export setup.yaml --host web01 --check-only

# Reproducible output for diff-review (drops the banner timestamp)
tack export setup.yaml --host web01 --no-banner-timestamp
```

## Flags

| Flag                  | Short | Type   | Default | Description                                                        |
|-----------------------|-------|--------|---------|--------------------------------------------------------------------|
| `--host`              |       | string | ""      | Target a single host                                               |
| `--all-hosts`         |       | bool   | false   | Emit one script per host in the inventory (requires `--out-file`)  |
| `--out-file`          | `-o`  | string | ""      | Output path: a file for `--host`, a directory for `--all-hosts`. Stdout when unset (single-host) |
| `--no-facts`          |       | bool   | false   | Skip fact gathering; fact references become sentinels              |
| `--check-only`        |       | bool   | false   | Validate and list unsupported constructs without writing files     |
| `--no-banner-timestamp`|      | bool   | false   | Omit the timestamp line for byte-identical, reproducible output    |
| `--extra-vars`        | `-e`  | string | ""      | Extra variables (`key=value`, repeatable)                          |
| `--tags`              |       | string | ""      | Only export tasks with these tags                                  |
| `--skip-tags`         |       | string | ""      | Skip tasks with these tags                                         |
| `--connection`        |       | string | ""      | Connection type for fact gathering (local, ssh, ssm, docker)       |
| `--inventory`         | `-i`  | string | ""      | Inventory source (repeatable)                                      |
| `--vault-password-file`|      | string | ""      | Path to file whose first line is the vault password                |

`--host` and `--all-hosts` are mutually exclusive. When neither is set and the
playbook resolves to a single host, that host is used automatically.

## Anatomy of an exported script

```bash
#!/usr/bin/env bash
set -euo pipefail
#
# Generated by tack export v1.2.3
# Playbook:   setup.yaml
# Host:       web01
# Exported:   2026-09-08T10:00:00Z
# Facts:      arch=x86_64 os_family=Debian os_type=Linux ...
#
# This is a SNAPSHOT. Re-export if playbook, inventory, or target facts change.
#
TACK_CHANGED=0
TACK_FAILED=0
TACK_CURRENT_TASK=""
on_exit() {
  local ec=$?
  if [[ $ec -ne 0 ]]; then
    echo "tack-export: FAILED on task: ${TACK_CURRENT_TASK}" >&2
  fi
  echo "tack-export: summary: changed=${TACK_CHANGED} failed=${TACK_FAILED}" >&2
  exit $ec
}
trap on_exit EXIT

# === TASK: install nginx === (tags: setup,web)
TACK_CURRENT_TASK='install nginx'
if ! dpkg-query -W -f='${Status}' 'nginx' 2>/dev/null | grep -q 'install ok installed'; then
  DEBIAN_FRONTEND=noninteractive apt-get install -y -qq --install-recommends 'nginx'
  TACK_CHANGED=$((TACK_CHANGED+1))
fi
```

Every task becomes one commented block. `set -euo pipefail` is in effect
throughout, and the `EXIT` trap reports the failing task and a change/failure
summary.

## What resolves at export time

| Construct              | Behavior                                                             |
|------------------------|---------------------------------------------------------------------|
| `{{ var }}`            | Interpolated against extra vars ∪ play/role vars ∪ vault vars ∪ facts |
| `template:`            | Rendered to final content and embedded as a heredoc with a diff guard |
| `when:`                | Evaluated; false tasks become `# SKIPPED (when false): <expr>`       |
| `loop:` (static/var)   | Unrolled into one block per item                                     |
| `tags` / `--tags`      | Filtered before emission; surviving tags shown in the block header   |
| `include_tasks` (static)| Inlined recursively (circular includes detected)                   |
| facts                  | Frozen at export time via the connector; echoed into the banner      |

## Supported vs unsupported constructs

**Supported modules:** `command`, `apt`, `brew`, `yum`, `file`, `copy`,
`template`, `lineinfile`, `blockinfile`, `systemd`, `user`, `group`, `cron`,
`git`.

**Unsupported (emitted as `# UNSUPPORTED: <reason>` with the original task YAML
as a comment, never silently dropped):**

- Handlers
- `block` / `rescue` / `always`
- `register` values consumed by later runtime logic (`when:` referencing a
  registered variable is included unconditionally with a `# WARN` note)
- `loop:` over a runtime-only source
- Dynamic / interpolated-path `include_tasks`
- Any module that does not implement shell export

`--check-only` prints a per-host summary of supported and unsupported tasks and
**exits non-zero** if any unsupported construct is found — suitable for CI gates.

## Determinism guarantees

Export output is deterministic: the **same inputs produce byte-identical
output**, with one exception (the banner timestamp). Specifically:

- All map iteration (task params, environment, facts, tags) is sorted by key
  before emission.
- Facts are rendered in sorted-key order in the banner.
- Loop expansion preserves the input list order.
- No random identifiers are embedded.
- The only non-deterministic line is the banner `# Exported:` timestamp. Pass
  `--no-banner-timestamp` to omit it and obtain byte-identical output across
  runs — ideal for committing exports to version control and diff-reviewing
  changes.

## Security notes

- **Vault secrets appear in plaintext.** The exported script needs decrypted
  values at runtime, so any vault value that flows into the output is written in
  the clear. When this happens, the banner carries a prominent warning:

  ```
  # WARNING: This script contains values decrypted from vault.
  # Treat this file as SECRET and do not commit to version control.
  ```

  Output files are written with mode `0600`.

- **`no_log: true` tasks** have their emitted commands wrapped to suppress
  stdout/stderr (`>/dev/null 2>&1`), matching the playbook's intent. When such a
  task is unsupported, its parameter values are redacted (`<redacted: no_log>`)
  in the embedded YAML comment.

## Workflows

### Audit workflow

Commit a reproducible export alongside the playbook and diff it in review:

```bash
tack export setup.yaml --host web01 --no-banner-timestamp --no-facts \
  --out-file audit/web01.sh
git add audit/web01.sh
# reviewers read the exact commands; CI re-runs export and fails on drift
```

### Air-gapped workflow

```bash
# On a connected control host:
tack export setup.yaml --host airgap01 --out-file airgap01.sh
# Transfer airgap01.sh to the target by whatever channel is available, then:
bash airgap01.sh
```

Validate before shipping with `bash -n airgap01.sh` (syntax) or
`bash -x airgap01.sh` (trace).
